Basics

Plan your dream trip and build a travel planner you can keep using.

Starting a project

  1. Create a folder. In Windows File Explorer or macOS Finder, create a folder such as travel-planner wherever you want to keep this project.

  2. Open that folder in your harness. Start a local project or session in Codex or Claude Code and choose this folder as the working directory. Select only this folder for the exercise, rather than your whole Documents or home folder, and check the path before sending the first prompt.

  3. Define the working scope. This folder is the agent’s starting point for files and commands. Other files may still be accessible, depending on permissions and sandbox settings; selecting a folder alone does not prevent all outside access. Tell the agent to stay here and ask before accessing files elsewhere. A broad request such as “find a PDF ticket for this trip somewhere in my files” may invite a wider search; be specific, such as “look for the ticket only in this project’s trips/lisbon-weekend/ folder.”

  4. Start new conversations in the same project. For this exercise, keep using the same local folder so each session can read its current saved files and project instructions. A new conversation does not automatically inherit every earlier chat or load every file into context. Ask it to read the README, instructions, handoff and relevant trip plan to pick up where you left off.

Vocabulary
Harness
The app around the model that manages tools, permissions and the session.
Context
The information supplied for the task, including conversation, instructions, relevant files and tool results.
Instructions
Standing project guidance, such as AGENTS.md or CLAUDE.md.
Skill
A reusable procedure in a folder containing SKILL.md.
Hook
A configured check triggered by an event, such as before a tool call.
Tool
An action an agent can call, such as searching online or reading a selected calendar.
Computer use
Working with an app through its screen, mouse and keyboard.
Worklog / handoff
A record of changes and saved context for continuing in another session.
Task
Create a reusable travel-planning folder and start planning your dream trip.
Learn
Write instructions, plan with sources, keep logs and reuse a checked procedure.
Workflow
Set up → research a trip → inspect → improve → hand off.
Example structure

Keep each trip in its own folder; start with one plan file and add more only when needed.

travel-planner/
├── README.md
├── AGENTS.md or CLAUDE.md
├── search-log.md
├── worklog.md
├── HANDOFF.md             # Added when you pause
└── trips/
    └── lisbon-weekend/
        └── plan.md

Each plan has a trip brief, accommodation, transport, activities and a day-by-day itinerary. Shared logs name the trip they refer to.

  1. Set the context

    Once your folder is open, initialize it and save lasting rules for your chosen harness, Codex or Claude Code.

    Inspect. Check the working folder’s path, then open it in VS Code and find the instructions: AGENTS.md for Codex or CLAUDE.md for Claude Code; check the file map and the rule about outside access.

  2. Plan your dream trip

    Choose somewhere you would love to visit, such as Lisbon; give possible dates, a budget and interests such as food and museums.

    Inspect. Open the plan in Markdown preview and check one accommodation or activity detail against its source; are the dates, price assumptions and daily pace sensible?

  3. Give feedback

    Improve the plan with ordinary feedback, such as a slower pace or replacing one paid activity with a free option.

    Inspect. Compare the changed lines in VS Code with your request; decide whether the correction belongs only to this trip or should become a project rule.

  4. Leave a handoff

    Save enough context to continue later, with a next step such as checking the accommodation’s cancellation policy.

    Try it. Start a fresh chat in this project and ask it to read the instructions and handoff, then summarize where to continue; check its answer against the files.

Go further

Try these after the first trip plan works, or follow the instructor's demonstration.

  1. Compare reasoning

    Use the same saved trip notes at two supported reasoning settings, for example to make a more relaxed itinerary.

    Try it. Run the prompt at two effort settings in the harness, using different output filenames; record the model, settings and time, then compare accuracy and usefulness.

  2. Work in parallel

    Ask one chat to coordinate parallel work, for example two relaxed itineraries from the same saved trip notes at different reasoning settings.

    Inspect. Compare the two results, then let the coordinating chat update the shared records; notice that project files can be shared while conversations have separate context.

  3. Make a skill

    Reuse the checked process for another trip you would like to take, such as a weekend in Vienna.

    Inspect. Open SKILL.md and the second trip’s plan; separate reusable steps from preferences that belong in the project instructions.

  4. Test a guardrail

    Follow a synthetic demonstration of folder protection using a fake booking confirmation rather than any real private file.

    Inspect. Check the observed block: instructions guide behaviour, .gitignore excludes untracked files from Git, and a trusted hook can block covered tool actions.

    Use only the prepared fake confirmation; keep real booking documents out of this demonstration.

  5. Keep work local

    Use global instructions for habits you want across projects, such as keeping working files in each project’s ignored .agent-work/ folder instead of temporary folders.

    Compare. Find the global and project instruction files; decide which preferences belong everywhere and which belong only to this project.
