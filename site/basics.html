Basics

Vocabulary
Harness
The app around the model that manages tools, permissions and the session.
Context
The information supplied for the task, including conversation, instructions, relevant files and tool results.
Instructions
Standing project guidance, such as AGENTS.md or CLAUDE.md.
Skill
A reusable procedure in a folder containing SKILL.md.
Hook
A configured check triggered by an event, such as before a tool call.
Tool
An action an agent can call, such as searching online or reading a selected calendar.
Computer use
Working with an app through its screen, mouse and keyboard.
Worklog / handoff
A record of changes and saved context for continuing in another session.
Task
Research a fictional train journey and save a useful comparison.
Learn
Write instructions, check sources, inspect changes and continue in a new session.
Workflow
Set context → look up → inspect → improve → hand off.

  1. Set the context

    Give the project lasting rules, using a name such as weekend-trips and your chosen harness, Codex or Claude Code.

    Inspect. Open the folder in VS Code and find the instructions: AGENTS.md for Codex or CLAUDE.md for Claude Code; check that the structure is easy to understand.

  2. Look up a journey

    Try a route such as Zurich to Bern on your chosen date, adding preferences such as second class with a Half Fare Travelcard.

    Inspect. Open the Markdown preview and a cited source; check one departure time or price, including its date and discount assumptions.

  3. Give feedback

    Improve the result with ordinary feedback, such as adding journey duration or making the table easier to scan.

    Inspect. Compare the changed lines in VS Code with your request; decide whether the correction belongs only to this journey or should become a project rule.

  4. Leave a handoff

    Save enough context to continue later, with a next step such as comparing the return journey.

    Try it. Start a fresh chat in this project and ask it to read the instructions and handoff, then summarize where to continue; check its answer against the files.

Go further

Try these after the first journey works, or follow the instructor's demonstration.

  1. Compare reasoning

    Use the same saved information at two supported reasoning settings to compare speed and quality.

    Try it. Run the prompt at two effort settings in the harness, using different output filenames; record the model, settings and time, then compare accuracy and usefulness.

  2. Work in parallel

    Ask one chat to coordinate parallel work, for example comparing the same saved journey options at two supported reasoning settings.

    Inspect. Compare the two results, then let the coordinating chat update the shared records; notice that project files can be shared while conversations have separate context.

  3. Make a skill

    Reuse the procedure you have checked, with another journey such as a return trip to Zurich.

    Inspect. Open SKILL.md and the new result; separate reusable steps from preferences that belong in the project instructions.

  4. Test a guardrail

    Follow a synthetic demonstration of folder protection using a fake ticket rather than any real private file.

    Inspect. Check the observed block: instructions guide behaviour, .gitignore excludes untracked files from Git, and a trusted hook can block covered tool actions.

    Download-only access needs a separately checked transfer workflow; use a prepared fake ticket here.

  5. Keep work local

    Use global instructions for habits you want across projects, such as keeping working files in each project’s ignored .agent-work/ folder instead of temporary folders.

    Compare. Find the global and project instruction files; decide which preferences belong everywhere and which belong only to this project.
