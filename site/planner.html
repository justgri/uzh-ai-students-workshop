Planner

Build a second brain that helps you pick up where you left off.

Task
Create a small home for projects, notes and plans.
Learn
Organize context, reuse a skill and keep project state across sessions.
Workflow
Set up → plan → capture an update → review → resume.

A second brain keeps useful context in linked notes you can inspect and maintain with an agent, inspired by Karpathy’s LLM Wiki.

Starting a project

  1. Create a folder. In Windows File Explorer or macOS Finder, create a folder such as planner wherever you want to keep this project.

  2. Open that folder in your harness. Start a local project or session in Codex or Claude Code and choose this folder as the working directory. Select only this folder for the exercise, rather than your whole Documents or home folder, and check the path before sending the first prompt.

  3. Define the working scope. This folder is the agent’s starting point for files and commands. Other files may still be accessible, depending on permissions and sandbox settings; selecting a folder alone does not prevent all outside access. Tell the agent to stay here and ask before accessing files elsewhere. A broad request such as “find my course deadlines somewhere in my files” may invite a wider search; be specific, such as “look for deadlines only in this project’s 02-projects/academic/ folder.”

  4. Start new conversations in the same project. For this exercise, keep using the same local folder so each session can read its current saved files and project instructions. A new conversation does not automatically inherit every earlier chat or load every file into context. Ask it to read the README, instructions, handoff and relevant project notes and plans to pick up where you left off.

Official guidance: Codex projects and chats · Codex permissions · Claude Code file access · Claude Code sessions

Example structure

Start with a few of your projects; add folders and planning views when you need them.

planner/
├── README.md
├── AGENTS.md or CLAUDE.md
├── FILE-INDEX.md
├── HANDOFF.md
├── 01-planning/
│   ├── today.md
│   ├── next-3-days.md
│   ├── next-7-days.md
│   └── longer-term.md
├── 02-projects/
│   ├── work/           # Job projects
│   ├── school/         # Courses, assignments
│   ├── hobbies/        # Hiking, shows, running
│   ├── admin/          # Paperwork, errands
│   └── travels/        # Trips
├── 03-worklogs/
│   └── timeline.md
├── 04-second-brain/    # Reference notes
└── 99-inbox/           # Notes to sort

Give content folders a short README and each project a note with its goal, current state and next action.

  1. Start a project

    Save the purpose of your planner as project instructions so the agent can use that context in later sessions.

    Inspect. Open the instructions file and check that it describes how you want to use the planner.

  2. Set the rules and scaffold

    Adapt the instructor’s instructions to your preferences, then create folders and notes for your areas and first projects.

    Download AGENTS.md · View and copy template

    Review. Check that the instructions match your preferences and each project sits in the right area with a useful next action.

  3. Borrow a skill

    Reuse the instructor’s planning skill to make realistic plans and record progress. Read its workflow and supporting checklist before installing it.

    Download planning skill · View and copy template

    Inspect. Open SKILL.md and check that its steps and required access fit your project.

  4. Make a plan

    Turn project context into a realistic plan, for example allowing two hours today and prioritizing a course deadline.

    Think. Is the plan realistic, and can you trace each action to a project? Tell the agent what to shorten or reprioritize.

  5. Capture an update

    Keep the planner current with a small update, such as finishing an outline while leaving the draft for tomorrow.

    Inspect. Review the diff in VS Code: is the right project updated, is its next action useful, and were unrelated notes left alone? Try a second update after giving feedback.

  6. Pick up later

    Leave enough context for the next session to continue, such as the current priorities and an unresolved deadline.

    Try it. Open a fresh chat in this project and ask it to read the handoff and suggest your next action; check the answer against the files.

Go further

  1. Read a calendar

    Add scheduling context from a shareable demo calendar, for example checking how much time remains around lectures.

    Check. Compare the summary with the demo calendar, including dates and timezone; review proposed plan changes before applying them.

  2. Track a meeting

    Turn fictional meeting notes into follow-up work, such as assigning the next step for a student-association event.

    Review. Can every decision and action be traced to the notes, and is any uncertain owner or date clearly marked?

  3. Build a local view

    Make selected notes easier to browse, for example showing project status and today’s next actions in one view.

    Compare. Check the dashboard against its source notes, then change one note and verify that the refreshed view reflects it.
