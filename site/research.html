Research

Make one research result trustworthy, then improve the way you repeat it.

Starting a project

  1. Create a folder. In Windows File Explorer or macOS Finder, create a folder such as research-project wherever you want to keep this project.

  2. Open that folder in your harness. Start a local project or session in Codex or Claude Code and choose this folder as the working directory. Select only this folder for the exercise, rather than your whole Documents or home folder, and check the path before sending the first prompt.

  3. Define the working scope. This folder is the agent’s starting point for files and commands. Other files may still be accessible, depending on permissions and sandbox settings; selecting a folder alone does not prevent all outside access. Tell the agent to stay here and ask before accessing files elsewhere. A broad request such as “find research notes somewhere in my files” may invite a wider search; be specific, such as “look for research notes and results only inside this project folder.”

  4. Start new conversations in the same project. For this exercise, keep using the same local folder so each session can read its current saved files and project instructions. A new conversation does not automatically inherit every earlier chat or load every file into context. Ask it to read the README, instructions, handoff and relevant research plan and results to pick up where you left off.

Task
Explore a small public research question, such as comparing research groups working on a topic you care about.
Learn
Define success, check sources, give feedback and turn a useful procedure into a reusable skill.
Workflow
One case → learn from three → make a skill → five new cases and timing comparison → feedback and skill update.

Start with one checked result; continue through three, a skill and five new cases if time allows. The larger pilot and automated batch are extensions.

  1. Set the direction

    Once your folder is open, choose your harness and a question you can check, such as finding research groups studying human–AI collaboration.

    Inspect. Check the working folder’s path and find the README and instructions: AGENTS.md for Codex or CLAUDE.md for Claude Code. Check the rule about outside access, then read the plan: could you tell whether a result meets it, and is the question small enough to check yourself?

  2. Prove one case

    Try one complete example first, such as a research group whose official website you can open.

    Check the sources. Open the links and verify the important claims; a matching topic does not prove that a group currently has an opening.

  3. Learn from three

    Use feedback to improve the method, for example by asking for clearer evidence or shorter summaries.

    Compare. Check all three results, including the ambiguous case, and confirm that the timing covers only the two new cases. Which problem needs a better rule, and which is a personal preference?

  4. Make a skill

    After reviewing the three cases, package the useful procedure as a skill with a name such as research-group-review.

    Inspect. Read the skill: does it capture your corrections and explain how to handle missing or ambiguous evidence?

  5. Use the skill on five new cases

    Try five research groups you have not checked yet, keeping the comparison within the same topic.

    Compare the time. Check that the averages use two new cases without the skill and five with it. Different cases can take different time; a faster average still needs a quality review.

  6. Verify and improve the skill

    Open the five new results’ sources yourself, then give feedback such as requiring clearer evidence for a claim.

    Review the changes. Confirm that your feedback changed the skill as well as the results, and check the corrected claims against their sources before using the skill on more cases.

Go further

  1. Compare a pilot

    As an extension, benchmark 20 cases and compare supported reasoning settings using the same checked examples.

    Decide. Does the quality justify doing more, and did extra reasoning help enough to justify the time? If you cannot complete the pilot, leave it pending.

  2. Divide the work

    As an extension, split independent items between sessions, such as separate lists of research groups.

    Inspect. Check for duplicated items or conflicting edits, and confirm that both sessions received the same procedure and preferences.

  3. Run a small batch

    As a final extension, try a small repeatable run, for example five remaining items within ten minutes.

    Check the trace. Find completed items, any unresolved cases and the next action in the saved files; could another session continue without repeating the work?
